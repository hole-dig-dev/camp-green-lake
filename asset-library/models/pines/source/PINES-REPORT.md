# Gold Fever: ten original pines

Built and visually refined in Blender 4.5.11. All geometry and vertex paint are generated by `pines.py`; there are no downloaded models, external textures, alpha cards, or animations.

`pines.blend` contains exactly ten scenes (`pine-01` through `pine-10`). Each has `.Near` and `.Far` collections containing the origin-centred export mesh, plus a `.Studio` collection with the preview pair, camera, lights, and ground. Preview copies share mesh data; the studio is excluded from every GLB.

All exports are in `gold-fever/public/assets/trees/`. Sizes below are exact bytes; `pines-manifest.json` provides the same data for tools.

Integration: metres, Blender +Z up converted to glTF +Y up. Every asset node has identity transforms. Its origin is the centre of the trunk base at ground level; geometry never extends below Y=0. Near and far versions use the same base, height, branch layout and crown-clump placements. Windswept leans toward +X before any game rotation.

Each file contains one mesh with two material primitives, `PineBark` and `PineNeedles`; the dead snag has one primitive and only `PineBark`. `GLTFLoader` creates a group with separate meshes for those primitives, suitable for instancing one batch per primitive. Both materials use white base factors and actual `COLOR_0` vertex paint. Preserve `vertexColors` and the exported normals when wiring them in. Lightning charring is dark vertex paint on `PineBark`. All surfaces are opaque; no textures or UVs are needed.

Rebuild everything, including the ten side-by-side near/far renders and contact sheet:

```bash
~/blender/blender -b --python gold-fever/art/blender/pines.py
```

The script relaunches its own background process with the Vulkan backend before rendering, and verifies AMD hardware rendering. It never contacts the Blender session on port 9876. The contact-sheet step uses the installed system Python/Pillow and DejaVu font to label the Blender PNGs. `-- --no-render` rebuilds and audits exports without drawing; `-- --only 05,06` rebuilds all assets but refreshes only those previews.

Visual review: inspected individual renders and `renders/pines-sheet.png` through multiple revisions. Refined crown density, uneven pointed boughs, forked leaders, raised bark plates, bare branch silhouettes, LOD supports and shading, and framing around the leaning tree. `renders/pines-three-review.png` shows the exported models under Three.js 0.180 with the game’s ACES exposure and sun/hemisphere settings; this is an isolated asset preview.

Validation: all twenty files passed triangle budgets, exact requested heights (within 0.1 mm), ground pivots, identity transforms, material names/counts, opacity and vertex-color checks. Independently decoded binary buffers: all positions finite, indices in range, normals unit length, every primitive has varying colors, and no external resources. Opened the saved blend and checked its ten scenes. All twenty files loaded successfully in Three.js 0.180 with vertex colors enabled and no browser errors on AMD/RADV.

An evenly distributed 140-tree instancing check (14 of each variant) used 19 draw calls: 460,376 near triangles or 95,172 far triangles, excluding shadows/ground. These are geometry counts, not a frame-rate benchmark. The near maximum is 4,410 triangles and the far maximum is 798.

Game modules and shared code are unchanged. The exports are ready for JT’s forest wiring; no push or merge was performed.
